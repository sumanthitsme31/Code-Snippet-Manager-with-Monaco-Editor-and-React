Objective
You will build a feature-rich code snippet management application using React and the Monaco Editor. You'll learn to integrate a powerful, industrial-strength code editor into a web application, manage complex application state, interact with external APIs like GitHub Gists, and implement advanced UI features like themes and local storage persistence. This project is a portfolio-worthy tool that mirrors real-world developer productivity applications.

Description
Background
In modern software development, productivity tools are essential. Code snippet managers help developers save, find, and reuse common pieces of code, eliminating repetitive typing and reducing errors. Integrating a full-featured code editor like Monaco Editor (the editor that powers VS Code) into a web application provides a superior user experience with features like syntax highlighting, auto-indentation, and theme support.

This project challenges you to build such a tool. You will leverage a modern frontend stack, focusing on component-based architecture with React, robust state management, and interaction with browser APIs like Local Storage and the Clipboard API. You will also integrate with the GitHub Gist API, a common requirement in developer-focused applications. The entire application will be containerized using Docker, ensuring a consistent development and evaluation environment, a standard practice in professional software engineering.

Implementation Details
Follow these steps to build the application. You have the freedom to structure your components and state as you see fit, as long as the core requirements are met.

Step 1: Project Setup
Initialize a new React application using your preferred toolchain (e.g., Create React App, Vite). Install the necessary dependencies, including react, react-dom, @monaco-editor/react, a routing library like react-router-dom, a state management library, and a CSS framework like Tailwind CSS.

Step 2: Containerization with Docker
Create a Dockerfile and docker-compose.yml at the root of your project to serve the application. This ensures your application can be run with a single command.

Here is a template for your docker-compose.yml:

# docker-compose.yml
version: '3.8'
services:
  web:
    build: .
    ports:
      - '3000:80' # Expose port 3000, mapped to port 80 in the container
    environment:
      - NODE_ENV=production
    healthcheck:
      test: ["CMD", "curl", "--fail", "http://localhost"] # Basic health check
      interval: 30s
      timeout: 10s
      retries: 3
Your Dockerfile should handle building the React application and serving the static files, for example using a multi-stage build with Node.js and Nginx.

Step 3: Core UI and Layout
Design a multi-panel layout. A common pattern is a sidebar for listing snippets and folders, a main content area for the code editor, and a header for controls like search and theme switching. Use react-router-dom to manage views for the main dashboard, individual snippets, and the shareable snippet page.

Step 4: Snippet Management and Local Storage
Implement the core CRUD (Create, Read, Update, Delete) functionality for snippets. All snippet data (ID, title, content, language, tags) must be persisted in the browser's localStorage. Create custom hooks or services to abstract the localStorage interactions.

Step 5: Monaco Editor Integration
Integrate the @monaco-editor/react component into your main view. Configure it to display snippet content, apply syntax highlighting based on the snippet's language, and switch between light and dark themes. Ensure the editor's content is synchronized with your application's state.

Step 6: Feature Implementation
Build out the application's features one by one, such as search/filtering, copy-to-clipboard, and theme switching. Refer to the core_requirements for the exact specifications of each feature.

Step 7: GitHub Gist API Integration
Implement the functionality to import from and export to GitHub Gists. You will need to make requests to https://api.github.com/gists. While full OAuth is not required, your application should be structured to use a personal access token from an environment variable for authenticated requests if available. For this task, anonymous Gist creation is sufficient for the export feature.

Step 8: Environment Configuration
Create a .env.example file to document any environment variables your application uses. This is critical for configuration and evaluation.

# .env.example
# A GitHub Personal Access Token can optionally be provided for authenticated API requests.
# This is not required for the core functionality but allows for higher rate limits.
REACT_APP_GITHUB_TOKEN=

Implementation Guidelines
These are advisory suggestions to guide your implementation, not strict requirements.

Architecture and State Management
Component Structure: Organize your UI into small, reusable components. Consider a structure like components/layout, components/editor, components/sidebar, components/SnippetList, etc.
State Management: For a complex application like this, using a dedicated state management library (like Zustand or Redux Toolkit) is recommended over relying solely on React Context. This helps manage global state like the snippet collection, user settings (theme), and API data more predictably. Use React Query or SWR for managing the state of API requests to GitHub.
Custom Hooks: Create custom hooks to encapsulate complex logic, such as useLocalStorage, useDebounce (for the search input), or useSnippets.
Performance and UX
Debounced Search: To avoid performance issues when searching through snippet content, debounce the search input so that the filter function only runs after the user has stopped typing for a brief period (e.g., 300ms).
Lazy Loading: The Monaco Editor can be a large bundle. Consider lazy loading the editor component using React.lazy() and Suspense to improve initial page load time.
Error Handling: Implement robust error handling for API requests. Display user-friendly notifications if importing or exporting a Gist fails.
Code Quality and Maintainability
Modularity: Keep your API interaction logic separate from your UI components. Create a dedicated service or module for handling GitHub API calls.
Consistency: Maintain a consistent coding style throughout the project. Use a linter and formatter like ESLint and Prettier to enforce this.
FAQ
Q: Do I need a backend server?

A: No, this is a frontend-only application. All data persistence is handled via the browser's localStorage as specified in requirement local-storage-persistence.
Q: Am I required to use a specific state management library?

A: No, you are free to choose any state management solution (React Context, Zustand, Redux, etc.). Your choice should be justified by your application's needs.
Q: How should I handle the GitHub API token for Gist export?

A: The application should be able to create anonymous Gists without a token. However, it should also be designed to optionally use a token from an environment variable (REACT_APP_GITHUB_TOKEN) for authenticated requests. This is detailed in requirement gist-export.
Q: What should the shareable snippet URL look like?

A: It should be a client-side route, for example /snippets/view/:snippetId. Your application's router should parse the snippetId from the URL and display the corresponding snippet in a read-only view, as per requirement snippet-sharing.
Q: Can I use a different code editor component?

A: No, the use of the Monaco Editor is a core part of this task, as specified in requirement monaco-editor-integration.
Q: How can I programmatically test the copy-to-clipboard functionality?

A: Automated testing frameworks like Playwright or Cypress provide APIs to interact with and verify the browser's clipboard content. This is how requirement copy-to-clipboard will be verified.
